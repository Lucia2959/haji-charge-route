# A. 보안

## A-1. 인증 · 접근 통제

### ✅ A-1-1. 공유 시크릿 기반 1차 차단

| | |
|---|---|
| **위험** | 인증 없는 공개 API. 봇·스캐너가 백엔드를 직접 호출해 외부 API 쿼터를 소진 |
| **처리** | `API_TOKEN` 설정 시 `/api/*` 요청에 `X-Haji-Key` 헤더를 요구. 불일치 시 401 |
| **위치** | `backend/app/main.py:require_token`, `frontend/src/lib/api.ts:req()` |
| **설계 판단** | 토큰이 번들에 노출되므로 **사람 대상 인증이 아니다.** 1차 차단용임을 코드 주석·문서에 명시 |
| **미들웨어 순서** | rate limit보다 **먼저 실행**되도록 나중에 등록 → 토큰 없는 요청이 정상 사용자의 제한 쿼터를 소모하지 않음 |
| **예외** | CORS preflight(`OPTIONS`)는 통과. 브라우저가 preflight에 커스텀 헤더를 싣지 않기 때문 |
| **검증** | `curl -o /dev/null -w "%{http_code}" https://<백엔드>/api/stations/TEST` → **401** |

### ✅ A-1-2. 로컬 개발 무마찰

`api_token`이 비어 있으면 검사를 건너뛴다. 로컬에서 헤더 없이 개발 가능.

## A-2. 요청 제한 (Rate Limiting)

### ✅ A-2-1. IP·경로별 인메모리 제한

| | |
|---|---|
| **위험** | 버튼 연타·자동 호출로 외부 API 쿼터가 순식간에 소진 |
| **처리** | 슬라이딩 윈도우(60초) 방식 IP·경로별 카운터 |
| **위치** | `backend/app/ratelimit.py` |
| **제한값** | `/api/route/plan` 20 · `places/search` 40 · `weather/current` 40 · `stations` 60 · 그 외 120 (분당) |
| **응답** | 429 + `Retry-After` 헤더 + 남은 초 안내 |
| **한계** | 프로세스 메모리 기반 → 다중 워커 부정확, 재시작 시 초기화. **외부 공개 시 Redis 교체 필요** |

### ✅ A-2-2. 프록시 IP 문제 해결

`render.yaml`의 `--proxy-headers --forwarded-allow-ips="*"`.
없으면 `request.client.host`가 항상 프록시 IP가 되어 **"IP당 20회"가 "전체 합산
20회"**로 동작한다 — 사용자 1명이 앱 전체를 묶는 **자가 DoS**.

### ✅ A-2-3. 메모리 무한 증가 방지

IP를 바꿔가며 요청하면 `(ip, prefix)` 키가 무한히 쌓인다.
→ `_sweep()`이 **5분마다** 윈도우가 지난 키를 걷어낸다.

### ✅ A-2-4. 프런트 측 연타 방지

새로고침 버튼 **8초 쿨다운** (`main/page.tsx:handleRefresh`).
실패 시에는 쿨다운을 즉시 해제해 바로 재시도할 수 있게 한다.

### ✅ A-2-5. react-query 재시도 축소

| | |
|---|---|
| **위험** | 기본값(retry 3)은 402(사용량 초과)·404에도 4회를 재시도해 쿼터를 더 태운다 |
| **처리** | 재시도 1회로 축소 + **402/404/"사용량" 응답은 즉시 포기** |
| **위치** | `frontend/src/app/providers.tsx` |

|---|---|

"공공데이터포털 한국환경공단 전기차 충전소 정보" 또는 "테스트용 mock 데이터"를

## A-5. 개인정보 · 위치정보

### ✅ A-5-1. 개인 주소를 번들·서버에서 제거

| | |
|---|---|
| **과거 결함** | 즐겨찾기(집·회사)를 `NEXT_PUBLIC_*` 환경변수로 두면 **빌드 산출물에 주소가 문자열로 박혀** 배포 URL만 알면 누구나 읽을 수 있다 |
| **처리** | 앱 내 "＋ 즐겨찾기" 버튼으로 등록 → **기기 localStorage에만** 저장 |
| **위치** | `lib/api.ts:loadShortcuts/saveShortcuts`, `main/page.tsx:setShortcut` |
| **주의** | 아이콘 배열(`SHORTCUT_ICONS`)만 코드에 있고 주소는 담지 않는다 |

### ✅ A-5-2. 브라우저 저장소 TTL

| 키 | 저장소 | TTL |
|---|---|---|
| `haji.routePlan` (경로 좌표 전체) | sessionStorage | **3시간** |
| `haji.mainForm` (출발·도착) | sessionStorage | **3시간** |
| `haji.selectedCharger` | sessionStorage | **3시간** |
| `haji.shortcuts` | localStorage | 사용자 삭제까지 |

만료·손상 데이터는 읽을 때 자동 삭제한다 (`loadWithTs`).

### ✅ A-5-3. 서버는 개인정보를 저장하지 않는다

DB가 없다. 요청 처리 후 좌표·주소를 남기지 않는다.
`_station_region`은 `statId → 시군구코드` 매핑일 뿐 개인정보가 아니다.

### ✅ A-5-4. 저장소 접근 실패 방어

Safari 프라이빗 브라우징·쿠키 차단·잠금 모드에서는 `sessionStorage` 접근 자체가
`SecurityError`를 던진다. 감싸지 않으면 **마운트 시점에 화면 전체가 죽는다.**
→ `saveWithTs` / `loadWithTs` / `removeSafe` 전부 try-catch. 저장소를 못 쓰면
조용히 포기하고 메모리 상태만으로 동작한다.

## A-7. 전송 · 헤더

### ✅ A-7-1. 공공 API HTTPS 전환

`EV_API_BASE = "https://apis.data.go.kr/..."` — HTTP 대신 HTTPS로 전송구간 보호.

### ✅ A-7-2. 보안 헤더

| 헤더 | 백엔드 | 프런트 |
|---|---|---|
| `X-Content-Type-Options` | `nosniff` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | 동일 |
| `X-Frame-Options` | **`DENY`** | `SAMEORIGIN` |

**위치:** `backend/app/main.py:security_headers`, `frontend/next.config.ts`

`setdefault`를 써서 라우터가 명시적으로 설정한 헤더는 덮지 않는다.

### ❌ A-7-3. CSP — 미적용

**사유:** 카카오 SDK가 인라인 스크립트를 사용해 `script-src 'unsafe-inline'`이
필요하다. `'unsafe-inline'`을 허용한 CSP는 XSS 방어 효용이 크게 떨어져, 추가
복잡도 대비 실익이 낮다고 판단해 보류했다.

**추가한다면:** `frontend/next.config.ts`의 `securityHeaders`에 넣는다.
카카오 지도 도메인(`*.daumcdn.net`, `*.kakao.com`)을 `script-src`·`img-src`·
`connect-src`에 허용해야 지도가 뜬다.

### ✅ A-7-4. 프런트 설정 오류 조기 감지

https 페이지에서 `NEXT_PUBLIC_API_BASE`가 `http://`이거나 `localhost`를 포함하면
콘솔에 `[설정 오류]`를 출력한다 (`lib/api.ts` 상단). 빌드 타임 주입이라 설정을
빠뜨리면 런타임에 조용히 깨지기 때문.

# B. 성능

## B-1. 캐싱

### ✅ B-1-1. 충전소 카탈로그 24시간 캐시 — **가장 큰 성능 레버**

| | |
|---|---|
| **문제** | 계획 응답시간의 **57%**(400km 기준 4.5초)가 시군구 24곳 카탈로그 수집 |
| **처리** | `_CATALOG_TTL = 24 * 3600` (6시간 → 24시간으로 상향) |
| **안전성** | 담는 내용이 위치·이름·출력·개방여부 같은 **거의 안 변하는 정적 메타데이터**. 신규 충전소 반영이 최대 하루 늦어질 뿐 |
| **실시간성** | 사용가능 여부는 별도 20초 캐시가 담당하므로 영향 없음 |
| **효과** | 캐시 히트 시 **계획 3초 안팎** (4.5초가 통째로 사라짐) |

### ✅ B-1-2. 실시간 상태 20초 캐시

`_STATUS_TTL = 20.0`. 충전소 상세는 10초마다 폴링하지만 실제 외부 호출은
20초에 1회.

### ✅ B-1-3. in-flight 요청 공유

| | |
|---|---|
| **문제** | 워밍업과 사용자 계산이 겹치면 같은 시군구를 두 번 받아 응답도 느려지고 쿼터도 두 배 소모. 400km 경로 하나가 시군구 20여 개를 부르므로 체감이 크다 |
| **처리** | `_catalog_inflight[key]`에 `asyncio.Task`를 등록해 **동일 조회를 공유** |
| **위치** | `ev_stations.py:_get_catalog` |

### ✅ B-1-4. 카탈로그 조회 시 상태캐시 선반영

`_fetch_catalog()`가 방금 받은 row로 `_status_cache`도 채운다.
→ 콜드 계획에서 같은 시군구를 상태용으로 다시 fetch하는 중복 호출 제거.

### ✅ B-1-5. 상태 병렬 프리페치

`warm_status()` — 경로가 지나는 시군구의 실시간 상태를 **중복 제거 후 병렬로**
미리 데운다. 이후 목적지·배정·대체 충전소 상태 조회가 전부 캐시 히트가 되어
순차 루프의 네트워크 대기가 사라진다.

### ✅ B-1-6. 만료 캐시 명시적 제거

`_status_cache`는 시군구 원본 row(건당 ~2.5KB)를 통째로 보관한다. TTL은 "읽을 때
만료 판정"만 하므로 엔트리를 안 지우면 프로세스가 사는 동안 계속 쌓인다
(장거리 1회 계산으로 수십~수백 MB).
→ `_evict_expired_status()`가 상태 조회 시점에 만료분을 삭제한다.

## B-2. 네트워크

### ✅ B-2-1. 공유 커넥션 풀

| | |
|---|---|
| **처리** | 매 호출 새 클라이언트 대신 **keep-alive 풀 재사용** → TLS 핸드셰이크 부하 제거 |
| **설정** | `httpx.Limits(max_connections=20, max_keepalive_connections=10)` |
| **정리** | 앱 종료 시 `lifespan`에서 `aclose()` |
| **위치** | `backend/app/http.py` |

### ✅ B-2-2. 동시성 상한 튜닝 — **실측 기반**

| 세마포어 | 상한 | 근거 |
|---|---|---|
| `_FETCH_CONCURRENCY` | **4** | **8로 올려 측정했더니 공공 API가 곧바로 차단. 4는 정상.** 올리면 오히려 계획이 실패한다 |
| `_KAKAO_CONCURRENCY` | 6 | 장거리는 샘플 30개+ → 무제한이면 Kakao 버스트 스로틀 |

> ⚠ **`_FETCH_CONCURRENCY`를 올려 속도를 개선하려는 시도는 이미 실패했다.**
> 병렬화로는 못 줄인다. 유일하게 효과적인 수단은 캐시를 살려두는 것.

### ✅ B-2-3. 페이지 수 최소화

`numOfRows = 9999` — 시도당 호출 수를 최소화(429 예방).
페이지 사이에 `_THROTTLE_SEC = 0.4` 지연.

### ✅ B-2-4. 재시도 · 백오프

| 대상 | 재시도 | 백오프 |
|---|---|---|
| Kakao (`_get_retry`) | 3회 | 0.5s × (n+1). 429·5xx·타임아웃·전송오류 |
| 공공 EV (`_get_with_retry`) | 3회 | 0.6s × (n+1). 429만 |

**쿼터 소진은 재시도하지 않는다** — 백오프 낭비 없이 즉시 `QuotaExceeded`.

### ✅ B-2-5. 워밍업 엔드포인트

`POST /api/route/warmup` — 앱 진입/복원 시 백그라운드로 카탈로그를 미리 데운다.
계획은 하지 않는다. 실패해도 조용히 무시.
**로딩 오버레이를 띄우지 않는다** (`withLoading`으로 감싸지 않음).

### ✅ B-2-6. 타임아웃 계층화

| 대상 | 값 | 근거 |
|---|---|---|
| 프런트 일반 조회 | 20초 | 충분 |
| 프런트 **경로계산** | **120초** | 콜드 캐시 시 실측 50초까지. 20초로 끊으면 서버는 정상 처리 중인데 "서버 연결 오류"가 뜬다 |
| 백엔드 Kakao 지오코딩·행정동 | 10초 | |
| 백엔드 Kakao 경로 | 15초 | |
| 백엔드 공공 EV | 20초 | |

## B-3. 알고리즘

### ✅ B-3-1. 사각박스 프리필터

| | |
|---|---|
| **문제** | 충전소 수천 개 × 경로 샘플 수백 개 완전탐색(haversine)이 **초 단위**로 느려진다 |

### ✅ B-3-2. DP 후보 축소

`_select_candidates()` — 경로를 20km 구간으로 나눠 구간당 상위 2개만 DP 노드로.
정렬은 `휴게소 우선 → 고출력 → 근접`.

### ✅ B-3-3. 거리 기준 샘플링

| | |
|---|---|
| **버그였던 것** | 정점 인덱스 기준 샘플링(`::n`)은 고속도로 직선구간에서 정점이 드물어 **큰 거리 공백**이 생긴다. 중간 충전소가 엉뚱한 지점(예: 0km)에 투영되거나 시군구를 통째로 놓쳤다 |
| **처리** | `sample_path_points(path, step_km)` — **거리 기준** 균일 샘플 |
| **사용처** | 시군구 탐색 12km / 근접 판정 2km / 투영 2km |

### ✅ B-3-4. CPU 시간은 이미 무시 가능

근접 필터·투영·DP 등 **CPU 전부가 0.4초(5%)**. 추가 최적화의 실익이 없다.
성능 개선은 캐시·네트워크 쪽에서만 나온다.

## B-4. 프런트 렌더링

### ✅ B-4-1. 지도 폴리라인 솎아내기

400km 경로는 정점이 8천 개까지 나온다. 그대로 그리면 팬/줌이 버벅인다.
→ 표시용으로만 **1200점 균등 샘플** (`step = ceil(길이/1200)`).
줌 12에서 시각적 차이 없음. **계산에는 원본을 쓴다.**

### ✅ B-4-2. 이미지 최적화

`next/image` + `sharp`. 로그인 로고는 `priority`(LCP 대상).
아이콘은 명시적 `width`/`height`로 레이아웃 시프트 방지.

### ✅ B-4-3. 로딩 깜빡임 방지

`useGlobalLoading(delayMs = 120)` — 120ms 미만 호출은 오버레이를 띄우지 않는다.

### ✅ B-4-4. 세션 복원으로 재계산 회피

화면 이동 후 돌아와도 sessionStorage에서 검색조건·계획을 복원한다.
불필요한 재계산 = 불필요한 외부 API 호출을 막는다.

### ✅ B-4-5. 기온 자동조회 중복 방지

- `hydrated` 이전에는 조회 안 함
- 복원 직후 1회는 `skipWeather` 플래그로 스킵 (복원한 기온을 덮어쓰지 않음)
- `cancelled` 플래그로 언마운트 후 setState 방지

cd backend

## F-3. 접근성 수동 검증

| 항목 | 방법 |
|---|---|
| 키보드만으로 전체 조작 | Tab / Shift+Tab / Enter / Space / ESC |
| 모달 포커스 트랩 | 모달 열고 Tab을 계속 눌러 내부 순환 확인 |
| 포커스 복귀 | 모달 닫은 뒤 원래 버튼에 포커스가 있는지 |
| 접힘 영역 | 접힌 상태에서 Tab이 내부 버튼을 건너뛰는지 |
| 확대 | iOS Safari에서 핀치 줌이 되는지 |
| 입력 확대 | 입력창 탭 시 화면이 자동 확대되지 않는지 |
| 스크린리더 | iOS VoiceOver로 메인 → 결과 → 충전소 상세 순회 |
| 색 대비 | 브라우저 devtools 또는 Lighthouse |
| 애니메이션 저감 | OS 설정 "동작 줄이기" 켜고 로더 확인 |
