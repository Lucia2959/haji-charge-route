## 2. 하드웨어 / 인프라

### 2.1 실행 환경

| 계층 | 플랫폼 | 사양 | 비용 |
|---|---|---|---|
| **프런트** | Vercel Hobby | 서버리스/Edge, 자동 HTTPS, 콜드스타트 없음 | 무료 (**비상업 전용**) |
| **백엔드** | Render Free | **512MB RAM**, 공유 CPU, Singapore 리전 | 무료 (월 750 인스턴스시간) |
| **크론** | cron-job.org | HTTP GET 스케줄러 | 무료 |
| **클라이언트** | iPhone Safari | — | — |

### 2.2 왜 이 조합인가

| 후보 | 판정 |
|---|---|
| **Vercel — 프런트** | Next.js 네이티브, HTTPS 자동, 콜드스타트 없음 |
| **Render — 백엔드** | 무료 512MB, **싱가포르**가 한국에서 가장 가까운 무료 리전 |
| ~~Vercel에 백엔드~~ | **함수 10초 타임아웃** — 경로계산이 3~50초라 불가. 서버리스는 인메모리 캐시가 매번 날아가 외부 API 쿼터를 태운다 |
| ~~Fly.io~~ | 2026년 무료 티어 종료 |
| ~~Railway~~ | $5 크레딧 소진 후 유료 |

### 2.3 아키텍처 제약 — **반드시 단일 인스턴스·단일 워커**

이 백엔드는 **인메모리 캐시와 rate limit 카운터**를 프로세스 메모리에 둔다.
따라서 다음이 강제된다.

| 제약 | 이유 | 위반 시 |
|---|---|---|
| `--workers 1` | 캐시·카운터가 프로세스 로컬 | 캐시가 워커 수만큼 쪼개지고, rate limit이 워커 수만큼 곱해짐 |
| 인스턴스 1개 | 동일 | 위와 같음 + 외부 API 쿼터 배수 소모 |
| 서버리스 금지 | 요청마다 메모리 초기화 | 매 요청이 콜드 카탈로그 빌드 → 쿼터 즉시 소진 |
| `--proxy-headers --forwarded-allow-ips="*"` | Render는 프록시 뒤에서 실행 | `request.client.host`가 항상 프록시 IP → rate limit이 "IP당 20회"가 아니라 **"전체 합산 20회"**가 되어 사용자 1명이 앱 전체를 묶는 자가 DoS |

> 확장이 필요해지면 Redis 등 공유 저장소로 캐시·카운터를 옮긴 뒤에야 다중 워커/
> 인스턴스가 가능하다. 그전까지는 위 설정을 **절대 변경하지 말 것.**

### 2.4 keep-alive 크론이 필수인 이유

Render 무료는 **15분 무요청 시 슬립**하며, 깨어날 때
`콜드스타트 30~60초` + `카탈로그 재빌드` 가 겹쳐 첫 사용이 1분을 넘긴다.

`/health`를 10분마다 호출하면 서비스가 잠들지 않아 **콜드스타트도, 카탈로그
재빌드도 없어진다.** Render 무료는 월 750 인스턴스시간이고 한 달은 ~730시간이라
**서비스 1개는 상시 가동해도 쿼터 안에 든다.**

- `/health`는 토큰 검사 대상이 아니므로 인증 없이 호출 가능
- **URL 오타 주의** — `/heath`가 아니라 `/health`. 계속 실패하면 잡이 자동 비활성화될 수 있음

### 3.3 미들웨어 체인 (실행 순서)

FastAPI는 **나중에 등록한 미들웨어가 먼저 실행**된다.

```
요청
 ↓
① CORSMiddleware            allow_origins=[FRONTEND_ORIGIN], GET/POST만
 ↓
② security_headers          X-Content-Type-Options / Referrer-Policy / X-Frame-Options
 ↓
③ require_token             /api/* 에 X-Haji-Key 검사 (OPTIONS는 통과)
 ↓
④ rate_limit_middleware     IP·경로별 분당 제한
 ↓
라우터
```

> **③이 ④보다 먼저 실행되도록 나중에 등록했다.** 토큰 없는 요청이 rate limit
> 카운트를 소모하지 않고 즉시 차단되게 하기 위함. 봇이 401을 맞으면서 정상
> 사용자의 제한 쿼터를 태우는 것을 막는다.
>
> **CORS preflight(OPTIONS)는 토큰 검사를 통과시킨다.** 브라우저가 preflight에는
> 커스텀 헤더를 실어 보내지 않기 때문이다.

### 3.4 캐시 아키텍처

```
┌──────────────────────────────────────────────────────────────────┐
│  _catalog_cache        zcode:zscode → (ts, [StationSummary])     │
│  TTL 24시간            위치·이름·출력·개방여부 = 거의 안 변하는   │
│                        정적 메타데이터                            │
│                        ★ 계획 응답시간의 57%를 좌우              │
├──────────────────────────────────────────────────────────────────┤
│  _catalog_inflight     zcode:zscode → asyncio.Task               │
│  (수명 = 조회 동안)     동시 요청이 같은 조회를 공유 → 중복 제거   │
├──────────────────────────────────────────────────────────────────┤
│  _status_cache         zcode:zscode → (ts, [원본 row])           │
│  TTL 20초              실시간 충전기 상태. 만료분은 명시적 evict   │
│                        (row 하나가 ~2.5KB → 안 지우면 메모리 누수) │
├──────────────────────────────────────────────────────────────────┤
│  _station_region       statId → (zcode, zscode)                  │
│  무기한                 상세 조회를 시군구 단위로 좁히는 인덱스     │
├──────────────────────────────────────────────────────────────────┤
│  _hits (ratelimit)     (ip, prefix) → deque[timestamp]           │
│  5분마다 sweep          윈도우 지난 키 제거 (IP 무한 증가 방지)    │
└──────────────────────────────────────────────────────────────────┘
```

**캐시 상호작용 — 콜드 계획의 중복 호출 제거**

`_fetch_catalog()`는 방금 받은 row로 **`_status_cache`도 함께 채운다.** 없으면
콜드 계획에서 같은 시군구를 상태용으로 다시 fetch하게 된다. row는 방금 받아
신선하고, 20초 뒤엔 정상적으로 실시간 재조회된다.

### 3.5 동시성 제어

| 세마포어 | 상한 | 대상 | 근거 |
|---|---|---|---|
| `_plan_sem` | **2** | `/api/route/plan` · `/warmup` 핸들러 | 요청 1건이 카탈로그 원본을 최대 수백 MB 점유 → 512MB 인스턴스 보호. 초과분은 **거절이 아니라 대기** |
| `_fetch_sem` | **4** | 공공 EV API 카탈로그/상태 조회 | **실측상 8이면 즉시 차단됨. 절대 올리지 말 것** |
| `_kakao_sem` | 6 | Kakao `coord2regioncode` | 장거리는 샘플 30개+ → 무제한이면 버스트 스로틀 |
| `httpx.Limits` | 20 conn / 10 keepalive | 전역 커넥션 풀 | 위 두 상한(10) + 세마포어 없는 directions/geocode 몫 |

**전부 모듈 전역이다.** 즉 상한은 "요청당"이 아니라 "서버 전체"다. 동시 사용자가
늘어도 외부 API 호출 속도는 고정되고, 대신 **각자의 대기가 선형으로 늘어난다**
(실측: 겹치지 않는 경로 1명 4.6초 → 5명 23초). 이건 쿼터 보호를 위한 의도된
트레이드오프이고, `_fetch_sem`을 올려 해결할 수 없다.

경로가 **겹치면** in-flight 공유가 이를 상쇄한다 — 같은 경로 5명이 동시에 계산해도
외부 호출은 24회로 유지되고 대기도 4.6초 그대로다.

> **in-flight 공유는 `asyncio.shield`로 await 한다.** 맨 await로 기다리면 대기자
> 한 명의 취소가 공유 Task로 전파되어 무관한 요청까지 죽는다
> (asyncio 수준 재현: `test_external_stability.py` 9번).
>
> **단, 현재 스택에서는 요청 경로로 트리거되지 않는다.** 실측(2026-08-01,
> starlette 1.3.1 / uvicorn 0.51.0): 클라이언트가 연결을 끊어도 **핸들러는 취소되지
> 않고 끝까지 실행된다.** 신·구 코드로 같은 시나리오를 A/B 했을 때 결과가 같았다
> (양쪽 모두 편승자 200). 지금은 방어적 조치이며, 실제 트리거는 서버 종료(재배포)
> 정도다. starlette가 연결 끊김 시 취소 동작을 버전에 따라 바꿔 온 이력이 있어
> 업그레이드 후 다시 도달 가능해질 수 있으므로 유지한다 — 비용이 없다.

## 4. 주요 시퀀스

### 4.1 경로 계획 (`POST /api/route/plan`) — 핵심 흐름

```
프런트                백엔드                    Kakao              공공 EV API
  │                     │                        │                     │
  ├─ plan(o,d,soc,t) ──▶│                        │                     │
  │                     ├─ geocode(origin) ─────▶│                     │
  │                     ├─ geocode(dest) ───────▶│                     │
  │                     ├─ get_directions ──────▶│  (경로+교통 2.3s)   │
  │                     │                        │                     │
  │                     ├─ effective_range_from_segments()  ← 순수계산  │
  │                     ├─ congestion_extra_kwh()           ← 순수계산  │
  │                     │                        │                     │
  │                     ├─ stations_near_path()                        │
  │                     │   ├─ sample_path_points(12km)                │
  │                     │   ├─ region_code() ×N ─▶│ (동시 6)           │
  │                     │   ├─ _get_catalog() ×M ──────────────────────▶│ (동시 4, 4.5s)
  │                     │   └─ bbox 프리필터 → haversine 12km 필터      │
  │                     │                        │                     │
  │                     ├─ warm_status() ────────────────────────────▶ │ (병렬 프리페치)
  │                     ├─ 목적지 3km 내 개방 충전소 탐색               │
  │                     ├─ plan_charging_dp()               ← 순수계산  │
  │                     │   └─ 실패 시 recommend_charging_stops()       │
  │                     ├─ _enrich_availability()  (캐시 히트)          │
  │                     ├─ origin_precharge_advice()        ← 순수계산  │
  │◀── RoutePlanResponse┤                        │                     │
```

**실측 시간 분해 (400km 경로, 콜드 캐시)**

| 단계 | 시간 | 비중 |
|---|---|---|
| 충전소 카탈로그 fetch (24개 시군구) | 4.5s | **57%** |
| 카카오 경로 조회 | 2.3s | 29% |
| 근접 필터·투영·DP 등 CPU 전부 | 0.4s | 5% |

캐시가 살아있으면 4.5초가 통째로 사라져 **계획이 3초 안팎**으로 끝난다.

### 4.2 워밍업 (`POST /api/route/warmup`)

```
앱 진입/복원 → warmupRoute() (백그라운드, 로딩 오버레이 없음)
   → geocode ×2 → get_directions → stations_near_path
   → 카탈로그 캐시 채움. 계획은 하지 않음.
   → 실패해도 조용히 무시 (사용자 흐름을 막지 않음)
```

### 4.3 충전소 상세 (`GET /api/stations/{id}`)

```
_station_region[id] → (zcode, zscode)
   → _status_rows(zcode, zscode)   TTL 20초 캐시
   → statId로 필터 → _build_detail()
```

> `_station_region`은 **카탈로그 조회 시에만 채워진다.** 서버 재시작 후 계획을
> 한 번도 돌리지 않은 상태에서 충전소 상세를 직접 열면 매핑이 없어 404가 난다.
> 정상 사용 흐름(계획 → 상세)에서는 문제되지 않는다.

## 6. 알려진 구조 부채

| 항목 | 내용 | 영향 | 권장 |
|---|---|---|---|
| **배터리 용량 중복 정의** | `charging.py:capacity_kwh` ↔ `lib/charge.ts:CAPACITY_KWH` | 한쪽만 고치면 화면 간 값 불일치 | 백엔드가 스펙을 응답에 실어 프런트가 받아쓰기 |
| **`ev_stations.py` 책임 과다** | API 클라이언트 + 캐시 + XML 파싱 + 접근성 판정 + mock | 파일 600줄, 변경 영향 파악 어려움 | 캐시·파싱·mock 분리 |
| **`main/page.tsx` 책임 과다** | 화면 + 상태 + API + 결과 표시 (860줄) | 동일 | 결과 표시 섹션 컴포넌트 분리 |
| **mock과 실데이터 혼재** | 같은 파일에 목 데이터 상수 | 운영 코드에 테스트 데이터 상주 | `services/mock/` 분리 |
| **로그인 화면에 인증 없음** | 진입 연출뿐 | 사용자 오인 가능 | 현재 "비공식 개인 테스트 앱" 고지로 완화 중 |
| **`_station_region` 무기한 상주** | 상한·TTL 없음 | 장기 가동 시 완만한 메모리 증가 | 실사용 규모에선 무시 가능, 필요 시 LRU |

> 이 항목들은 **동작에 문제가 없고** 현재 규모에서 실익이 작아 의도적으로 남겨둔
> 것이다. 기능 추가 시 해당 파일을 건드리게 되면 그때 함께 정리하는 것을 권장한다.
