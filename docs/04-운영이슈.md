## 1. 속도 이슈

### 1.1 [I-S01] 첫 계산이 최대 1분 걸린다 ⚠ **가장 흔한 문의**

| | |
|---|---|
| **증상** | 계산 버튼을 눌러도 로딩이 40~60초 지속. 멈춘 것처럼 보임 |
| **빈도** | 캐시가 비었을 때 (서버 재시작 후, 크론 중단 후) |
| **영향** | 사용자 이탈. 타임아웃 오해 |

**원인 — 실측 시간 분해 (400km 경로, 콜드 캐시)**

| 단계 | 시간 | 비중 |
|---|---|---|
| 충전소 카탈로그 fetch (24개 시군구) | 4.5s | **57%** |
| 카카오 경로 조회 | 2.3s | 29% |
| CPU 전부 (근접 필터·투영·DP) | 0.4s | 5% |

여기에 Render 콜드스타트(30~60초)가 겹치면 1분을 넘긴다.

**❌ 병렬화로는 못 줄인다.** 동시 호출을 4 → 8로 올려 측정했더니 공공데이터 API가
**곧바로 호출초과로 차단**했다(4는 정상). `_FETCH_CONCURRENCY`는 건드리지 말 것.

**✅ 조치 (적용됨)**

| 조치 | 효과 |
|---|---|
| 카탈로그 캐시 TTL 6h → **24h** | 캐시 히트 시 4.5초가 통째로 사라져 **계획 3초 안팎** |
| **keep-alive 크론** 10분 간격 `/health` | 슬립 방지 → 콜드스타트·캐시 소실 없음 |
| **워밍업 엔드포인트** (`/api/route/warmup`) | 앱 진입 시 백그라운드 선행 로드 |
| in-flight 공유 (`_catalog_inflight`) | 워밍업과 사용자 계산이 겹쳐도 중복 호출 없음 |
| `warm_status()` 병렬 프리페치 | 배정·대체·목적지 충전소 상태 조회가 전부 캐시 히트 |
| 상태캐시 선반영 (`_fetch_catalog`) | 콜드 계획에서 같은 시군구를 두 번 안 받음 |
| 프런트 타임아웃 20s → **120s** | "서버 연결 오류" 오표시 제거 |
| 경과 시간별 안내 문구 | 4초/12초에 "1분까지 걸릴 수 있어요" 표시 |

**🔧 점검 순서**

1. cron-job.org 잡이 살아 있는가? URL이 `/health`인가 (`/heath` 오타 주의)
2. `curl https://<백엔드>/health` — 첫 응답이 30초 넘으면 슬립 중이었던 것
3. Render 대시보드에서 최근 재시작(배포·환경변수 저장) 여부 확인
4. 남는 2.3초(카카오 경로 조회)는 **외부 API라 단축 불가**

### 1.3 [I-S03] 메모리 증가 (Render 무료 512MB) ⚠ **잔여 리스크 있음**

| | |
|---|---|
| **원인** | `_status_cache`가 시군구 원본 row(건당 ~2.5KB)를 통째로 보관. TTL은 "읽을 때 만료 판정"만 하므로 엔트리를 안 지우면 계속 쌓인다 |
| **조치 (적용됨)** | `_evict_expired_status()` — 상태 조회 시 만료 엔트리 명시적 삭제 |
| **조치 (적용됨)** | `ratelimit._sweep()` — 5분마다 윈도우 지난 (ip, prefix) 키 제거 |
| **조치 (적용됨)** | `_plan_sem = Semaphore(2)` — 동시 실행을 제한해 피크가 겹치는 것을 막음 |
| **점검** | Render 대시보드 → Metrics → Memory. 512MB에 근접하면 재시작(캐시 초기화) |

**실측 — 요청 1건의 `_status_cache` 점유량**

| 시군구당 충전기 | 시군구 1곳 | 경로 24곳 |
|---|---|---|
| 1,000기 | 2.0 MB | 48 MB |
| 3,000기 | 6.1 MB | **146 MB** |
| 8,000기 | 16.2 MB | **389 MB** |

**⚠ 남아 있는 문제 두 가지**

1. **만료 제거가 요청 중에만 돈다.** `_evict_expired_status()`는 `_status_rows()`
   안에서만 호출되는데, keep-alive 크론은 `/health`만 친다 → **요청이 없는 동안엔
   만료 캐시가 전혀 안 지워지고**, 피크가 다음 요청까지 그대로 상주한다.
2. **`_station_region`은 상한·TTL이 없다.** 장기 가동 시 완만히 증가한다.

OOM → Render 재시작 → 캐시 전멸 → 다음 요청 다시 콜드, 라는 악순환이 가능하다.

**권장 후속 조치 (미적용)** — `_status_cache`에 원본 row 전체 대신 `_build_detail()`이
쓰는 필드만 담거나, 엔트리 수에 상한(LRU)을 둔다. 현재는 `_plan_sem`으로 피크 중첩만
막아둔 상태다.

### 1.4 [I-S04] 동시 접속 시 모두가 느려진다 — **구조적 특성**

| | |
|---|---|
| **증상** | 혼자 쓸 땐 10초인데, 여러 명이 동시에 계산하면 전원이 비례해서 느려짐 |
| **원인** | `_fetch_sem`(4)·`_kakao_sem`(6)이 **모듈 전역**이라 서버 전체가 슬롯을 나눠 쓴다 |

**실측 (겹치지 않는 경로, 카탈로그 수집 구간만)**

| 동시 사용자 | 각자 대기 |
|---|---|
| 1명 | 4.6s |
| 2명 | 9.2s |
| 3명 | 13.8s |
| 5명 | **23.0s** |

**✅ 완화되는 경우** — 경로가 겹치면 in-flight 공유가 살려준다.
같은 경로 5명 동시 → 외부 호출 24회 유지, 대기 4.6초 그대로.

**❌ 해결할 수 없는 것** — `_FETCH_CONCURRENCY`를 올리면 공공 API가 즉시 차단한다.
이건 쿼터 보호를 위한 의도된 트레이드오프다.

**✅ 적용된 보호 (2026-08-01)** — `_plan_sem = Semaphore(2)`로 동시 실행을 2건으로
제한했다. 초과분은 **거절이 아니라 대기**한다. 어차피 외부 API 동시성이 4로 고정이라
병렬로 밀어 넣어도 총 처리량은 늘지 않고, 메모리 피크와 커넥션 풀 압박만 커지기
때문이다. 검증: 동시 6건 → 동시 실행 최대 2, 전부 200, 총 1.26초(이론 1.2초).

### 2.3 [I-B03] 외부 API 일일 쿼터 소진

| | |
|---|---|
| **증상** | 화면에 **"사용량이 초과하였습니다"** (HTTP 402) |
| **원인** | 계산 1회 = 공공 EV API 시군구 약 **20~24회** + 카카오 지오코딩 2 + 경로 1 + 좌표변환 최대 30여 회 |
| **회복** | **일 단위 리셋.** 그날 안에는 회복되지 않는다 |
| **한도 확인·증량** | 공공데이터포털 마이페이지 → 오픈API → 활용신청 현황 |

**402 vs 429 — 반드시 구분한다**

| 코드 | 의미 | 화면 문구 | 회복 |
|---|---|---|---|
| **402** | 쿼터 **소진** | "사용량이 초과하였습니다" | 다음 날 |
| **429** | 단시간 **과다호출** | "요청이 몰리고 있습니다. 잠시 후 다시…" | 수 분 |

> 공공데이터포털은 쿼터 소진을 **두 형태**로 보낸다.
> (a) HTTP 200 + XML `returnReasonCode 22`
> (b) HTTP 429 + **평문** `"API token quota exceeded"` ← 게이트웨이 레벨
>
> (b)를 상태코드만 보고 "일시적"으로 처리하면, 실제로는 그날 회복되지 않는데
> "잠시 후 다시 시도"라고 잘못 안내하게 된다. → `_is_quota_body()`가 **본문까지
> 확인**해 구분한다. 이 로직을 건드리지 말 것.

**쿼터 절약 수칙**

- 캐시를 살려둔다 (크론 유지) — 카탈로그 재빌드가 가장 큰 소모원
- 새로고침 버튼 연타 금지 (8초 쿨다운이 걸려 있음)
- 충전소 상세 화면을 열어둔 채 방치하지 않는다 (20초당 1회)
- `_FETCH_CONCURRENCY`를 올리지 않는다 (오히려 차단당해 재시도로 더 소모)

### 2.4 [I-B04] 앱 자체 요청 제한이 인메모리다

| | |
|---|---|
| **현재** | `ratelimit.py` — 프로세스 메모리 기반. IP·경로별 분당 카운터 |
| **한계** | 다중 워커/인스턴스에서는 부정확. **재시작 시 카운터 초기화** |
| **적정성** | 개인/내부용으로는 충분. 외부 공개·상용에서는 **Redis 등 공유 저장소 기반으로 교체 필요** |

**현재 제한값**

| 경로 | 분당 |
|---|---|
| `/api/route/plan` | 20 |
| `/api/route/warmup` | 10 |
| `/api/places/search` | 40 |
| `/api/weather/current` | 40 |
| `/api/stations` | 60 |
| 그 외 `/api/*` | 120 |

> **`_bucket()`은 `startswith` 매칭이라 prefix를 빠뜨리면 조용히 기본값(120)으로 샌다.**
> `/api/route/warmup`이 그 사례였다 — plan과 비용이 사실상 같은데(지오코딩·경로조회·
> 카탈로그 수집을 그대로 수행) `/api/route/plan`에 안 걸려 6배 헐거운 제한을 받고
> 있었다. 2026-08-01에 전용 버킷(10/분)을 추가했다.
> 라우트를 추가하면 **버킷 매칭을 반드시 확인할 것**
> (회귀 검증: `test_external_stability.py` 10번).

**분당 제한은 동시 실행을 막지 않는다.** 20건이 같은 순간에 들어올 수 있다.
동시 실행 상한은 별도로 `_plan_sem`(2)이 담당한다 — [I-S04] 참조.

> `--proxy-headers --forwarded-allow-ips="*"`가 **없으면** 모든 사용자가 프록시 IP
> 하나로 묶여 "전체 합산 20회/분"이 된다. `render.yaml`의 이 옵션을 지우지 말 것.

### 2.5 [I-B05] 개인 위치정보 취급

| 데이터 | 저장 위치 | 보관 | 근거 |
|---|---|---|---|
| **즐겨찾기 주소** (집·회사) | **기기 localStorage만** | 사용자가 삭제할 때까지 | 서버·번들 어디에도 남기지 않음 |
| 검색조건 (출발/도착) | sessionStorage | **3시간 TTL** | 만료 시 자동 삭제 |
| 경로 계획 결과 (좌표 전체) | sessionStorage | **3시간 TTL** | 동일 |
| 선택 충전기 | sessionStorage | **3시간 TTL** | 동일 |

> **과거 결함:** 즐겨찾기를 `NEXT_PUBLIC_*` 환경변수로 두면 빌드 산출물에 주소가
> 문자열로 그대로 박혀 **배포 URL만 알면 누구나 읽을 수 있다.** 그래서 앱 내
> "＋ 즐겨찾기" 버튼으로 등록하는 방식으로 바꿨다. 되돌리지 말 것.

**서버는 개인정보를 저장하지 않는다.** DB가 없고, 요청 처리 후 좌표를 남기지 않는다.

### 2.6 [I-B06] mock 폴백이 실제 데이터처럼 보일 위험

| | |
|---|---|
| **위험** | 지오코딩 실패 시 "서울"로, 경로 실패 시 "직선거리×1.3"으로 조용히 폴백하면, 사용자는 **실제 경로인 줄 알고 주행**하게 된다. 있지도 않은 충전소를 추천할 수도 있다 |
| **조치** | 운영은 `MOCK_ENABLED=false`. 실패 시 폴백 대신 **오류 반환** (400 / 502 / 빈 목록) |
| **추가 조치** | 그래도 mock이 섞이면 화면에 **앰버 경고 배너** (`data_source === "mock"`) |
| **점검** | Render 환경변수 `MOCK_ENABLED`가 `false`인지 확인. `true`면 위험 |

### 2.7 [I-B07] CORS · 보안 헤더

| 항목 | 설정 |
|---|---|
| CORS 오리진 | `[FRONTEND_ORIGIN]` **단일 오리진만** (와일드카드 아님) |
| CORS 메서드 | `GET`, `POST`만 |
| CORS 헤더 | `Content-Type`, `Authorization`, `X-Haji-Key` |
| 백엔드 헤더 | `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY` |
| 프런트 헤더 | 위 3종 (단 `X-Frame-Options: SAMEORIGIN` — 자기 도메인 iframe 허용) |
| **CSP** | **미적용** — 카카오 SDK가 인라인 스크립트를 써서 `'unsafe-inline'`이 필요하다. 효용이 낮아 보류 |

> `FRONTEND_ORIGIN`은 **끝 슬래시 없이** 넣는다. 슬래시가 붙으면 오리진 문자열
> 비교가 실패해 CORS가 통째로 막힌다.

## 3. 기능·안정성 이슈

### 3.1 [I-F01] 오프라인 대응 없음

서비스워커가 없어 **터널·음영지역에서 앱을 새로 열면 오류 화면**이 뜬다.
이미 열려 있던 화면은 sessionStorage 복원으로 계속 볼 수 있다.

> 추가하려면 오프라인 셸(정적 자산 캐시)만으로 충분하다. API 응답은 실시간성이
> 중요하므로 캐시하지 말 것.

### 3.2 [I-F02] 지도가 안 뜬다

| 확인 순서 | 내용 |
|---|---|
| 1 | `NEXT_PUBLIC_KAKAO_JS_KEY`가 설정되어 있는가 (없으면 목록 폴백이 뜸) |
| 2 | **JavaScript 키에 도메인이 등록되어 있는가** ← 가장 흔한 원인 |
| 3 | 카카오맵 제품 사용 설정·무료 쿼터 상태 |

**도메인 등록 경로 (2026-07-21 콘솔 개편 후)**

```
앱 설정 → 앱 → 플랫폼 키 → [JavaScript 키] 선택 → JavaScript SDK 도메인
값: https://haji-charge-route.vercel.app
```

> ⚠ **REST API 키가 아니라 JavaScript 키**를 열어야 한다. REST 키 화면에도 비슷한
> 입력칸(호출 허용 IP, 리다이렉트 URI)이 있어 헷갈리기 쉽다.
> 예전의 "플랫폼 → Web → 사이트 도메인" 경로는 더 이상 없다.

### 3.3 [I-F03] 계산이 "서버 연결 오류"로 실패

| 확인 | 내용 |
|---|---|
| `NEXT_PUBLIC_API_BASE`가 `http://`인가 | https 페이지에서 http 백엔드를 부르면 Safari가 **mixed content로 전부 차단**. 콘솔에 `[설정 오류]` 로그가 찍힌다 |
| `localhost`가 들어 있는가 | 아이폰에서는 자기 자신을 가리켜 100% 실패 |
| 끝에 슬래시가 붙었는가 | `https://api.example.com/` → URL이 `//api/...`가 됨 |
| `FRONTEND_ORIGIN` 불일치 | CORS 차단. 브라우저 콘솔에 CORS 오류 |
| 120초를 넘겼는가 | 콜드스타트 + 콜드 캐시가 겹친 극단 케이스 |

> `NEXT_PUBLIC_*` 값을 바꿨으면 **반드시 Vercel Redeploy.** 빌드 시 번들에 굳는다.

### 3.4 [I-F04] `feasible=false` (완주 불가)

정상 동작이다. 경로상 도달 가능한 충전소가 없거나, 현재 충전량으로는 첫 충전소에도
못 가는 상황. 화면에 빨간 경고 + 선충전 권장이 함께 뜬다.

DP가 실패하면 greedy로 폴백하고, greedy도 실패하면 `feasible=false`가 된다.

## 5. 절대 건드리면 안 되는 설정

| 설정 | 위치 | 이유 |
|---|---|---|
| `_FETCH_CONCURRENCY = 4` | `ev_stations.py` | 8이면 공공 API가 **즉시 차단**. 실측 확인 |
| `asyncio.shield(inflight)` | `ev_stations.py:_get_catalog` | 빼면 한 요청의 취소가 공유 Task로 전파돼 무관한 요청까지 죽는다 |
| `_PLAN_CONCURRENCY = 2` | `routers/route.py` | 올리면 메모리 피크가 곱해져 512MB에서 OOM. 처리량은 어차피 `_fetch_sem`이 결정 |
| `--workers 1` | `render.yaml` | 캐시가 쪼개지고 rate limit이 워커 수만큼 곱해짐 |
| `--proxy-headers --forwarded-allow-ips="*"` | `render.yaml` | 없으면 rate limit이 "전체 합산"이 되어 자가 DoS |
| `MOCK_ENABLED=false` | Render 환경변수 | `true`면 가짜 경로·충전소가 실제처럼 표시됨 |
| REST 키 "호출 허용 IP" 비워두기 | Kakao 콘솔 | Render 무료는 아웃바운드 IP 비고정 |
| `_is_quota_body()` 본문 검사 | `ev_stations.py` | 402/429 구분이 여기서 결정됨 |
